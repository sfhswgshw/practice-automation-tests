# UI-автотесты для practice-automation.com

Проект UI-автотестов для страниц с упражнениями сайта
[practice-automation.com](https://practice-automation.com/):

| Страница | URL |
|---|---|
| Календарь | https://practice-automation.com/calendars/ |
| Модальные окна | https://practice-automation.com/modals/ |
| Рекламные окна | https://practice-automation.com/ads/ |
| Форма (п.5 задания) | https://practice-automation.com/form-fields/ |

**Стек:** Python 3.12+, Selenium 4, Pytest 8, Allure (allure-pytest), паттерн Page Object.

**Итого:** 51 тестовый сценарий (53 запуска с учётом параметризации): на каждую из трёх
страниц задания — 7–10 позитивных и 4–5 негативных, плюс сценарии страницы с формой
для п.5. Все тесты проходят в Chrome (Windows 11 и Ubuntu в GitHub Actions) и в Firefox (Ubuntu в GitHub Actions).

## Установка и запуск

Нужны **Python 3.12+** и установленный браузер **Google Chrome** или **Mozilla Firefox**.
Драйверы (chromedriver / geckodriver) отдельно ставить не нужно: Selenium 4 скачивает
подходящую версию автоматически (Selenium Manager).

```bash
git clone https://github.com/sfhswgshw/practice-automation-tests.git
cd practice-automation-tests

python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

Запуск:

```bash
pytest                              # все тесты, Chrome в headless-режиме
pytest --headed                     # с видимым окном браузера
pytest --browser firefox            # в Firefox
pytest tests/test_calendar.py       # тесты одной страницы
pytest -m negative                  # только негативные сценарии (также: positive, smoke)
pytest -k "TestModalsPositive"      # по имени класса / теста
```

Параметры можно задать и переменными окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BROWSER` | `chrome` | `chrome` или `firefox` |
| `HEADLESS` | `true` | запуск без окна браузера |
| `BASE_URL` | `https://practice-automation.com` | адрес сайта (или `--site-url`) |
| `TIMEOUT` | `15` | явное ожидание элементов, с |
| `BLOCK_ADS` | `true` | блокировать сторонние баннеры Google в Chrome (см. ниже) |
| `WINDOW_WIDTH` / `WINDOW_HEIGHT` | `1920` / `1080` | размер окна |

## Allure-отчёт

Результаты автоматически пишутся в `allure-results/` (задано в `pytest.ini`).
Для просмотра нужен [Allure CLI](https://allurereport.org/docs/install/)
(требуется Java 8+):

```bash
# Windows (Scoop):  scoop install allure
# macOS:            brew install allure
# любая ОС с Node.js: npx allure-commandline serve allure-results

allure serve allure-results
```

Что есть в отчёте:

- тесты сгруппированы **Epic → Feature (страница) → Story (позитивные / негативные)**;
- у каждого теста осмысленное название с ID сценария из этого README (`TC-CAL-01. …`)
  и уровень важности (severity);
- все действия описаны шагами на русском языке («Нажать кнопку «Form Modal»»,
  «Выбрать в календаре дату 2026-12-15 (пагинация)», …);
- при падении теста к нему прикладываются **скриншот**, URL и HTML страницы;
- на главной странице отчёта — блок Environment (браузер, режим, URL, размер окна).

В GitHub Actions тесты запускаются на каждый push, а собранный HTML-отчёт
сохраняется в артефакт `allure-report` (вкладка **Actions** → запуск → Artifacts).

## Архитектура и принятые решения

- **Page Object + компоненты.** Страницы (`pages/*_page.py`) описывают только свои
  элементы и действия. Повторяющиеся на разных страницах виджеты вынесены
  в компоненты: `Popup` (окна Popup Maker — простое окно, окно с формой и реклама
  устроены одинаково), `JetpackForm` (форма на странице календаря и форма в модальном
  окне — одна и та же технология), `DatePicker`.
- **Только явные ожидания** (`WebDriverWait`), никаких `time.sleep`. Там, где нужно
  проверить, что что-то *не* произошло (окно не закрылось, реклама не появилась
  повторно), используется ожидание с ограниченным временем.
- **Независимые тесты:** для каждого теста запускается новый браузер.
- **Селекторы** привязаны к устойчивым атрибутам: `id`, `name`, `data-*`, классам
  виджетов. Ошибки валидации находятся через `aria-describedby` поля, поэтому не
  зависят от сгенерированных WordPress идентификаторов.
- **Задержка рекламы** измеряется по `performance.now()` самой страницы, поэтому
  проверка не зависит от скорости загрузки страницы в WebDriver.
- **Сторонняя реклама Google** (AdSense) в Chrome по умолчанию блокируется через
  `--host-resolver-rules`. Всплывающая «реклама» на странице `/ads/` — собственное
  окно сайта (плагин Popup Maker), на него блокировка не влияет, а баннеры Google
  перестают перекрывать элементы и замедлять загрузку. Отключается `BLOCK_ADS=false`.
- **П.5 задания.** Раздел *Automation tools* и поле *Message* находятся на странице
  с формой **Form Fields**. Список получается методом `FormFieldsPage.automation_tools()`
  (XPath: пункты `<li>` списка сразу после подписи «Automation tools»), объединяется
  через `", "` и вводится в Message методом `fill_message_with_automation_tools()`.
  Результат: `Selenium, Playwright, Cypress, Appium, Katalon Studio`.

## Тестовые сценарии

Обозначения: **П** — позитивный, **Н** — негативный.
Все сценарии автоматизированы; ID совпадает с названием теста в Allure-отчёте.

### 1. Календарь — /calendars/

Функционал страницы: поле «Select or enter a date» (формат `YYYY-MM-DD`),
при фокусе открывается календарь (неделя начинается с понедельника, листание
месяцев стрелками, выбор года и месяца из списков, управление с клавиатуры);
кнопка Submit отправляет дату на сервер и показывает сообщение
«Thank you for your response.» со сводкой; ссылка «← Back» возвращает к форме.

затемнением страницы; закрыть его можно только кнопкой «×»; после перезагрузки
